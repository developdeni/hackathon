## 1. О продукте и цепочке ценности

**Tanap AI** — мобильный терминал агрономического мониторинга для фермеров и агрономов (Акмолинская область, Казахстан).
**Главная продуктовая цепочка:**
> **Спутник (Sentinel-2)** → **Детекция аномалий вегетации (NDVI/NDMI)** → **Выделение устойчивых очагов риска** → **Диспетчеризация агронома** → **Полевой выезд с фото и GPS** → **Локальная история и валидация**.

## 2. Стек технологий и архитектура

- **Mobile Client:** React Native (Expo SDK 57 / TypeScript), iOS Native Release build с вшитым Hermes `main.jsbundle`.
  - Целевое устройство: iPhone 13 (`Danil`, `00008110-001425580A50201E`).
  - Шрифты: Google Fonts **Montserrat** (`Montserrat_400Regular`, `Montserrat_500Medium`, `Montserrat_600SemiBold`, `Montserrat_700Bold`).
  - UI стиль: iOS Inset Grouped, строгий промышленный интерфейс без декоративного AI-слопа.
  - Сеть: `EXPO_PUBLIC_API_URL`; локальная сборка использует стабильное mDNS-имя `http://MacBook-Air-deni.local:8000`, поэтому смена Wi-Fi/подсети не требует менять IP в приложении.
  - Хранение сессии: JWT и последний подтверждённый профиль сохраняются в `@react-native-async-storage/async-storage`. Сетевой сбой не удаляет сессию; очистка выполняется только при явном выходе или ответе сервера `401/403`.
- **Backend:** FastAPI (Python 3.14), Uvicorn (`0.0.0.0:8000`), SQLite (`backend/data/tanap.db`), фото в `backend/data/uploads/`.
  - Авторизация: Argon2 password hashing + JWT (python-jose).
  - Геометрия: расчёт площади по локальной эквидистантной проекции и периметра по Haversine из сохранённого GPS-контура; это расчётная геометрия, не кадастровое измерение.
  - Аналитика: наблюдения NDVI/NDMI из Copernicus, относительные зоны по сетке, модельные метеоданные Open-Meteo и полевой прогноз урожайности по фактической истории. Отсутствующие значения возвращаются как null; подстановка числовых заглушек запрещена.

## 5. Интеграции и источники данных

1. **Copernicus Sentinel-2 L2A (10м)**:
   - Статус: **ПОДКЛЮЧЁН И АКТИВЕН** (OAuth Client Credentials в `backend/.env`).
   - Каналы: B04 (Red), B08 (NIR), B11 (SWIR), SCL (маска облаков и теней).
   - Индексы: реальные `NDVI` и `NDMI` рассчитываются через **Sentinel Hub Statistical API** (`sh.dataspace.copernicus.eu`).
   - Эндпоинт: `GET /api/fields/{id}/satellite` отдаёт живые спутниковые наблюдения с временным рядом за лето-осень.
   - Автосегментация: `POST /api/fields/auto-boundary` строит предварительный многоточечный контур пашни вокруг клика по NDVI, NDMI, яркости и спектральным границам. Используется снимок 256×256 за безоблачное окно 180 дней. `qualityScore` — эвристика поддержки спектральной границей и компактности, а не вероятность правильности; площадь приблизительна и итоговый контур обязан оставаться редактируемым.
   - Временной ряд: Statistical API загружает 210 дней с интервалом 10 дней и сеткой около 10 м. Интервал явно подписывается как период, а не дата отдельного снимка. NDVI/NDMI маскируются по SCL; отдельный output `quality` с исходной dataMask даёт доли облачных и пригодных доступных пикселей без учёта площади вне полигона. Отбрасываются NaN, менее 8 валидных пикселей и менее 30% пригодных пикселей. Медиана и разброс берутся из реальных перцентилей. SWIR-канал для NDMI имеет исходное разрешение 20 м.
   - Зоны: Shapely обрезает каждую ячейку по полю. Сравниваются только качественные наблюдения одного интервала с покрытием не менее 60% площади; средние взвешиваются по площади. Период, покрытие и статус сохранённых данных доступны в API и на экране. Устойчивость аномалий по времени не считается подтверждённой. Денежная экономия без исходных затрат не рассчитывается.
   - Классификация: эвристика NDVI требует минимум 6 качественных периодов одного сезона с весной и июнем–августом. «Вероятно в обороте» и «Возможное неиспользование» являются оценками, а не подтверждённым юридическим/агрономическим статусом.
2. **Агрометеорология Open-Meteo**:
   - `https://api.open-meteo.com/v1/forecast`: модельные текущие условия и прогноз на следующие 7 дней, даты, осадки, ET₀, GDD (база 5°C), водный баланс осадки−ET₀. Ветер явно запрашивается в м/с. Прогноз не выдаётся за измерения на поле или уже выпавшие осадки.
   - При сбое допускается только ранее полученный для тех же координат прогноз с исходной датой и пометкой `cached`; при отсутствии кэша возвращаются `unavailable` и null. Климатические индексы 0–100 являются пороговыми оценками, не вероятностями; пропуски погодных данных не заменяются числами.
   - CSV содержит отдельные строки `satellite_interval` и `weather_model_snapshot` с датами и источниками: современная погода не подставляется напротив исторических спутниковых дат. PDF корректно отображает отсутствие погоды.
3. **Прогноз урожайности 2.1**:
   - Эндпоинты: `GET/POST /api/fields/{id}/yield-history`, `DELETE /api/fields/{id}/yield-history/{record_id}`, `GET /api/fields/{id}/yield-forecast`.
   - Модель строится отдельно для конкретного поля и текущей культуры. Требуются минимум 4 фактических завершённых сезона; используются максимум 8 последних сопоставимых сезонов.
   - Признаки: пик NDVI и средний NDMI из Sentinel-2, сезонные осадки и GDD из NASA POWER, водный баланс осадки−ET₀ из ERA5. ERA5 запрашивается через Open-Meteo Archive API с явным `models=era5`; первоисточник реанализа — Copernicus Climate Data Store.
   - Алгоритм: стандартизация признаков и ridge regression с регуляризацией. 80% прогнозный интервал строится по абсолютным ошибкам leave-one-season-out conformal validation. На экране показываются MAE такой проверки и вклад каждого признака в т/га; вклад не объявляется причинным эффектом.
   - Открытая статистика Бюро национальной статистики РК показывается как справочный источник и не подмешивается в полевую модель без проверенной привязки к району, культуре и единицам. Данные партнёров входят только как явно внесённый пользователем фактический урожай.
   - При нехватке истории, Sentinel или погодного покрытия API возвращает `insufficient_data` / `unavailable` и список пропусков, а не синтетический прогноз.
4. **Оптимальные сроки сева и уборки 2.3**:
   - Эндпоинт `GET /api/fields/{id}/operations-recommendation` объединяет 16-дневный прогноз Open-Meteo и сезонную динамику Sentinel-2 по конкретному полю.
   - Для сева/посадки ищутся двухдневные окна внутри календаря культуры. Учитываются температура почвы на глубине 6 см, влажность слоёв 1–9 см, ночной минимум, осадки и ветер. Дни, для которых погодная модель не отдала почвенные показатели, не используются для рекомендации сева.
   - Для уборки ищутся трёхдневные окна с минимумом осадков, низкой вероятностью дождя, приемлемой влажностью воздуха, ветром и отсутствием заморозка. Дальний прогноз может использоваться без почвенных показателей, поскольку для уборочного окна они не являются обязательным входом.
   - Готовность к уборке не определяется календарём в одиночку: требуется сезонный пик NDVI и последующее снижение. Статусы «вероятное созревание» и «приближение к созреванию» являются спутниковой эвристикой; влажность зерна/продукции и проходимость поля подтверждаются полевым измерением.
   - Поддержаны календарные профили яровых зерновых, озимой пшеницы, рапса, льна, подсолнечника, кукурузы и картофеля. Для неизвестной культуры сервис честно сообщает об отсутствии проверенного профиля.
   - Оценка окна 0–100 — результат пороговых правил пригодности, не вероятность успешного сева или уборки. Доверие к дальнему прогнозу снижается после 5 и 10 дней.
5. **Локальная БД SQLite**:
   - Таблицы: `users`, `farm_profiles`, `fields`, `inspections`, `yield_history`. Каскадное удаление осмотров и истории урожайности при удалении поля.
6. **Gemini Vision / AI-агроном**:
   - Результат фото — интерпретация модели, не измерение и не подтверждённый диагноз. Некалиброванный self-confidence модели не показывается как «точность».
   - Доля симптомов означает приблизительную долю видимой растительной части кадра, не площадь поля. Потери урожая по одному фото не рассчитываются.
   - Подсчёт всходов является визуальной оценкой числа объектов. Плотность на м² и эквивалент на га рассчитываются сервером только из введённой пользователем площади рамки; для видео без постоянного масштаба плотность не считается.
   - Проценты зерновой пробы относятся к видимым объектам кадра, не к массовой доле. Класс, влажность, белок и клейковина требуют лаборатории. Поголовье по фото — предварительная оценка, особенно при перекрытиях и плотном стаде.
   - Если Gemini недоступен, сервер возвращает честную недоступность или региональный детерминированный агрономический синтез по фактической структуре культур без выдуманных лабораторных анализов.
   - Эндпоинт `GET /api/profiles/{profile_id}/ai-summary` агрегирует структуру посевов, площадь и статус полей профиля, отдаёт 2-3 предложения оперативной AI-сводки, умные статусы полей (`AI: Оптимум вегетации`, `AI: Очаг риска ~X га`, `AI: Окно СЗР 2 дня`, `AI: Рейтинг A+`) и 4 быстрых вопроса для перехода в чат с агрономом.

## 6. Стратегия на хакатон (Трек 1 — GIS и ДЗЗ)

- **Конкурсное позиционирование**: «Мобильная система раннего обнаружения устойчивых проблемных зон внутри поля по данным Sentinel-2, переводящая спутниковые аномалии в целевые задания полевого скаутинга».
- **Валидация**: сокращение выездов, снижение ложных тревог и экономия денег ещё не подтверждены полевым экспериментом. Ранее приведённые 92%, 52% и 770 000 ₸ были презентационными оценками; их нельзя представлять как измеренный результат.
